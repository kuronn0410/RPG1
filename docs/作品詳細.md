## 概要

Unityを用いて個人開発した3DアクションRPGです。  
プレイヤーは町で武器やカードを準備し、戦闘マップで敵を倒して経験値とお金を集めます。獲得した資源を使って武器購入やカード編成を行い、ステージを進めて3つのステージのクリアを目指します。

特徴は、アクション操作に加えて、最大5枚のカードデッキを編成して戦闘中に使用できる点です。  
武器の切り替えとカード効果を組み合わせ、状況に応じた戦い方ができるようにしています。

## ゲーム進行

- タイトル画面から新規ゲーム開始、セーブデータから続行、ゲーム終了が可能
- 町と戦闘マップを行き来しながらステージを進行
- 戦闘マップでは敵3体をランダム配置し、全敵撃破後に帰還用UI／扉を解放
- ステージ3のボスステージの敵を全て倒すとゲームクリア
- HPが0になるとゲームオーバー
- タイトルへ戻る処理を実装
- セーブデータ読込後、Loading画面を表示しながらTownシーンを非同期ロード

## 実装機能

### プレイヤー操作

- WASD移動
- マウスによる左右回転・カメラ上下回転
- カーソルのロック／解除
- ポーズ中の操作停止
- 左クリックによる武器攻撃
- 前進・攻撃・防御などのアニメーション連携

### ステータス・成長

- HP／最大HP、レベル、基礎攻撃力、経験値、お金を管理
- 敵撃破時に経験値とお金を獲得
- 必要経験値到達でレベルアップ
- レベルアップ時にHPを全回復
- ステージレベル管理を実装

### 武器システム

- 剣、鎌、バールのようなものを実装
- 武器ごとに攻撃力を設定
- 武器の所持管理
- 購入済み判定
- 装備武器の切り替え
- 装備変更時に武器Prefabを生成・持ち替え

### 敵システム

- 通常敵4種類、ボス1種類の敵データを管理
- マップ開始時に敵3体をランダム配置
- ボスステージではボスも配置
- プレイヤーとの距離に応じた追跡と攻撃
- 敵HP、死亡処理、全敵撃破判定
- 敵アニメーション
- スタン状態
- 毒による継続ダメージ
- 透明化中のプレイヤーを追跡しない処理

### カードシステム

- カードの所持管理
- 最大5枚のデッキ編成
- デッキへの追加・削除
- 数字キー1〜5でカードを使用
- 使用後はデッキから削除
- カードショップでの購入

実装済みカード効果：

- HP回復
- 攻撃力上昇
- 最大HP上昇
- 次の攻撃への毒付与
- 周囲の敵をスタン
- 一定時間敵から認識されなくなる透明化

### UI・インタラクション

- プレイヤーHP、レベル、経験値、お金、ステージ表示
- 敵HP表示
- ダメージ数字の3枠Queue表示
- 敵付近へのダメージ表示位置指定
- ゲームオーバー画面
- ゲームクリア画面
- ポーズメニュー
- 武器ショップ
- カードショップ
- 武器変更画面
- カード所持・デッキ・使用UI
- World Space UIのHover・クリック判定
- 画面中央からのRaycastによる商人・扉・World Spaceボタンとのインタラクション
- インタラクション時の操作方法表示
- マウス感度スライダー
- FPS（30／60／120）設定UI
- シーン遷移中のLoading画面とParticle演出
- レベルアップ時に画面中央へ一定時間 `LevelUP` の文字を表示
- World Space UIのRaycastを一定フレーム間隔で実行し、毎フレーム処理を抑制

### サウンド

- タイトル、街、戦闘、クリア時にBGMを切り替え
- 攻撃命中、敵死亡、レベルアップ、購入時などにSEを再生
- UI音は共通管理
- プレイヤー・敵の行動音は各オブジェクト側で再生
- プレイテストを基に、状態変化が伝わりやすいようSEを追加

### セーブ・ロード

- ゲームデータと設定データを別々のJSONファイルへ非同期保存・読込
- 新規ゲーム時のデータ初期化
- 以下のゲームデータを保存
  - レベル
  - 現在HP
  - 経験値
  - お金
  - 装備中の武器
  - 所持武器
  - ステージ進行度
  - デッキ内カード
  - 所持カード
- マウス感度とFPS設定を `settings.json` へ保存し、ゲーム開始時に復元
- async／awaitで処理完了を待機
- try-catch-finallyで例外処理とLoading画面の後処理を実装
- `SceneManager.LoadSceneAsync` による非同期シーン遷移

## プレイテスト

自分だけでは気付くことのできない、実際にプレイした際の不便さを発見するため、知人にプレイテストを行ってもらいました。

初めは一人の協力者にプレイしてもらい、そこで得た意見から改善効果が大きいと判断したものを優先して修正しました。

その後、同じ方に再度プレイしてもらい、

**プレイテスト → 修正 → 再テスト**

の流れで、改善できているか、新たに気になる点がないかを確認しています。

修正が一定以上進んだ段階で、複数人によるテストへ切り替える予定です。

### 改善内容

| プレイテストで得た意見 | 修正内容 |
|---|---|
| 操作方法が分かりにくい | 操作ガイドを追加 |
| インベントリのお金の表示に気付けない | お金を使用するショップ画面にも所持金UIを追加 |
| お金を使用している感覚が弱い | 購入時にSEを追加 |
| ゲームクリアが分かりにくい | BGM変更、敵死亡演出と消滅完了後にクリア画面を表示 |
| レベルアップに気づきにくい | SE＋視覚演出を追加 |
| 敵を倒した感じが弱い | 敵死亡時の縮小演出を追加 |
| Ray操作が分かりにくい | 十字UI＋操作表示を追加 |
| 武器の切り替えが分かりにくい | SE追加、選択中の文字表示、選択時に色が変わる枠を追加 |

## 工夫した点

### カードデッキシステム

カードデッキ管理を独自に実装し、プレイヤーが所持カードから最大5枚のデッキを編成し、戦闘中に数字キーで使用できるようにしました。

カードには、

- 回復
- 攻撃力上昇
- 毒付与
- スタン
- 透明化

など複数の効果を用意し、武器攻撃だけでなく状況に応じた戦略的な選択ができるようにしています。

### 責務を意識したクラス分割

プログラムは機能ごとにクラスを分割し、

- 敵管理
- カード管理
- ショップ管理
- セーブ機能
- UI管理

などの責務を分けました。

これにより、機能追加や不具合修正を行う際に影響範囲を把握しやすくし、保守性を高めています。

### ScriptableObjectによるデータ管理

敵やカードなどのデータはScriptableObjectで管理し、データと処理を分離しました。

プログラムを大きく変更せずにカードや敵の追加、パラメータ調整を行えるため、拡張性と開発効率の向上につながっています。

### UI更新

プレイヤーHP、経験値、お金、敵HP、ダメージ表示などのUI更新にはC#イベントを利用し、値の変化があったときだけ表示を更新する構成にしました。

UIとゲームロジックの直接依存を抑え、更新処理の責務を分けています。

### 非同期処理

ゲームデータと設定データは別々のJSONファイルに分離し、ファイル読み込みとシーン遷移にはasync／awaitを導入しました。

処理完了を待ってから次へ進む流れを明確にし、try-catch-finallyによって失敗時にもLoading画面を閉じられるようにしています。

### 設定保存のデバウンス処理

マウス感度はスライダー操作のたびに保存せず、コルーチンで最後の操作から一定時間待って保存するデバウンス処理を実装しました。

ポーズ中でも待機できるよう `WaitForSecondsRealtime` を使用しています。
