## 未改善

| 問題・気になった点 （優先度）| ステージのレベルを参照している場所が散らばり過ぎている(3) | 
| ------------ | --------- |   
| 原因・問題だと考えた理由 | PlayerLevelDataのステージ進行度がstaticでどこからでも参照できるため、各クラスが直接ステージレベルを参照して処理を分岐するようになっている。その結果、 ステージのレベルごとの処理が散らばりすぎていてどこでどんな処理が起こっているかわかりにくい
| 改善案  |　ステージレベルに応じた処理をまとめる責務を持つクラスを作成する。

| 問題・気になった点 （優先度）| EnemyStatusのセットアップのステータス (2)|  
| ------------ | --------- |   
| 原因・問題だと考えた理由 | セットアップですべてを一つずつコピーしている。後でEnemyParameterを増やした時に
毎回修正し直さないといけないと考えられるから。
| 改善案  |　 EnemyStatusがEnemyParameterの型を持ってそれにコピーする

| 問題・気になった点 （優先度）| 近くにいる敵の検知　(3)| 
| ------------ | --------- |   
| 原因・問題だと考えた理由 |　攻撃されてる敵ではなくていちばんちかくの他の敵のHPが表示されることがある。どの敵にダメージが入ったかわかりにくい。
| 改善案  | HP表示の対象を「最も近い敵」ではなく「現在攻撃対象になっている敵」として管理し、対象が死亡する・一定条件から外れるまでは別の敵へ切り替わらないようにする。 |

| 問題・気になった点 （優先度）| DamageTextUIのダメージ表記の方法| 
| ------------ | --------- | 
| 原因・問題だと考えた理由 |  攻撃されてる敵ではなくていちばんちかくの他の敵のダメージUIが表示されることがある。どの敵にダメージが入ったかわかりにくい。
| 改善案  | ダメージを受けた敵を検知するイベントを作る。

## 優先度
* **1：致命的ではない**
  現状でも動作し、作品完成への影響が小さい。時間があれば改善する。
* **2：改善したい**
  保守性・分かりやすさ・拡張性などに問題があり、余裕があれば対応する。
* **3：優先して改善**
  バグにつながる、変更しづらい、責務が大きく崩れているなど、今後の開発への影響が大きい。
